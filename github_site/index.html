Pretraining a 752M Encoder–Decoder for Text Rewriting

Model 752M-parameter encoder–decoder Trained 15 Sep – 25 Oct 2026 Hardware 1 × NVIDIA A100 40 GB Pretraining complete Comparison: partial results
Abstract

1Model

The 752M model is a sequence-to-sequence Transformer built for controllable rewriting: given text and a requested style, it returns one rewrite that means the same thing and keeps URLs, code, numbers and names exactly as written. That fidelity requirement drove the architecture. A bidirectional encoder reads the entire input before generation starts, and the decoder attends back to it through cross-attention at every step, so copying a span verbatim is a lookup rather than an act of memory.

2Data

The pretraining data comes from seven public datasets, all under licenses that allow commercial use: educational and general web text, synthetic textbooks, permissively licensed source code, public-domain books and two small command-line references. The token budget is 63.05 billion raw tokens under the model's own tokenizer, which is 68.48 billion processed tokens once the sentinel tokens and objective formatting are added. The SentencePiece tokenizer reserves 896 pieces for command-line vocabulary such as flags and utilities.

How the data was read

Files were read one at a time in a fixed shuffled order, and each file holds a single dataset, so training saw blocks of consecutive steps from one dataset. Lines were shuffled within files. From step 81,000 a separate reader served the cooldown blend, which mixes datasets in every batch, and one batch in five carried a synthetic rewriting task built from the prose datasets. Over the run the model processed . No dataset is read more than once.

The learning rate followed a warmup–stable–decay schedule. The final 10% of steps also switched the data to a curated cooldown blend, weighted toward educational text, code and command-line material, with a synthetic rewriting exercise in one batch in five.

The decay stage: cooldown data and the synthetic rewriting task

The last 9,000 steps (81,000 to 90,000) changed two things at once: the learning rate decayed to zero, and the data stopped following the on-disk order. A cooldown reader drew documents from a curated blend in every batch, weighted toward educational web text, textbooks, permissively licensed code and command-line references. Each source was capped at about eight passes over itself so the small command-line sets were not memorised. The reason for changing the data as well as the learning rate is that the decay alone mostly lowers loss, while an up-weighted high-value mixture is what tends to move downstream quality.

One batch in five (20%, drawn per batch with a seeded generator) was not a UL2 batch at all. It was a synthetic rewriting exercise in the exact shape the product uses: the encoder receives <style:grammar> <text_to_rewrite> damaged text </text_to_rewrite> and the decoder must produce the original text. The pairs are built on the fly from ordinary prose documents from the pretraining datasets, so the model meets the rewriting frame, and learns to copy what is already correct, before any fine-tuning. The reserved style and frame tokens were already in the frozen vocabulary, so this needed no change to the embedding table.

How the text is damaged

The one rule is that the original must be the unique right answer. Every operator produces a genuine writing error whose correction is the source text. There is deliberately no synonym swapping: replacing "big" with "large" is not a mistake, and a target that reverses it would teach the model to edit text that was never wrong. Code, URLs, paths, numbers, identifiers, e-mail addresses and anything in backticks or angle brackets are protected spans that pass through unchanged on both sides, and lines that are not prose (code, tables, headings, bare links) are copied verbatim, so every example also trains copy-through.

Three things stop the inverse from being a lookup table. Severity is sampled per document from three profiles, so the model cannot assume how much is wrong. The operator is sampled per word, so the same word is a homophone swap in one document and a typo in the next. And a slice of documents is left untouched, because "this text is already correct, copy it" is a case the product meets constantly.

Documents with fewer than eight prose words are skipped, and a document that does not fit the encoder or decoder length budget is skipped and counted rather than cut. In the run, the task read 1,376,936 documents, skipped 51,540 as not prose (3.7%), skipped none for length, and emitted 1,325,396 pairs containing 80.1 million damaged words, about 60 per pair, from 0.55 billion source tokens. The untouched share came out at 6.0% against the 5% target. Its training loss fell to about 0.05 nats per token by the end (Figure 15), far below the 1.0 to 2.0 of the UL2 denoisers, because most of the output is a copy of the input. That is the intended behaviour: the task teaches precise edits inside a faithful copy, not new text.

Why this is in pretraining

The rewriting adapters start from a model that has already seen the style token and the text-to-rewrite frame, instead of meeting them cold in fine-tuning. The reader's random state and position are saved in every checkpoint, so an interrupted run replays the same damage on resume.

Optimizer parameter groups

Learning rates at the peak of the schedule, as logged per group. The two special groups exist because AdamW moves every parameter by about the learning rate per step whatever its size, which was too slow for the small position-bias tables and too fast for the tiny T5 query initialisation (see section 5).
